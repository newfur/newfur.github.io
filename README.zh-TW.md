# Edge 網頁版電子書閱讀器 (Edge E-Book Reader)

Language: [简体中文](README.md) | **繁體中文** | [English](README.en.md)

[![Platform](https://img.shields.io/badge/platform-Chrome%20%7C%20Edge%20%7C%20Web-blue)](javascript:;)
[![License](https://img.shields.io/badge/license-ISC-green)](javascript:;)

一款專為網頁和瀏覽器設計的現代、美觀、功能強大且高度定制化的電子書閱讀器。項目集成了多格式解析器、高品質 Microsoft Edge 雲端神經網路語音朗讀（TTS）、本地 AI 閱讀助手以及精美的閱讀統計分析，支持**瀏覽器擴充功能（外掛）**、**本地 Web 服務 (PWA)** 以及**單檔案離線版**三種形態。

---

## 📖 專案簡介

本專案旨在打破電子書閱讀的平台限制，提供最頂級、最流暢的跨裝置閱讀與聆聽體驗。特別針對**微軟 Edge 神經網路語音**進行了深度適配與技術突破，使您無需安裝複雜的用戶端，即可在任何主流 Chromium 瀏覽器中享受媲美真人的有聲書朗讀。

---

## ✨ 核心特性

### 1. 🗂️ 廣泛的電子書格式支援
內置輕量級純 JS 解析引擎，支援多種主流電子書及文件格式的本地解析與渲染：
*   **EPUB**: 完整支援章節目錄、樣式渲染、圖文混排及多級跳轉。
*   **AZW3 / MOBI**: 相容 Kindle 格式，支援解析內嵌的樣式與圖片。
*   **TXT / MD (Markdown)**: 智慧提取章節標題與段落，自動構建目錄樹。
*   **FB2**: 完備支援小說段落和排版。
*   **CBZ (漫畫)**: 支援圖片打包漫畫的瀑布流或單頁閱讀。

### 2. 🎨 極致的個性化排版系統
*   **版面佈局**: 支援 **「左右模擬翻頁」**（雙頁排版）與 **「上下連續滾動」** 模式。
*   **字型支援**: 內置霞鶩文楷 (LXGW WenKai)、思源宋體 (Noto Serif)、OpenDyslexic (易讀字型)、Fira Code (等寬代碼)、Inter (無襯線) 等，支援調整大小、行高、字距。
*   **視覺主題**: 預設明亮白、深雅灰、復古紙、極簡綠、純黑 (OLED)、櫻花粉、海洋藍、石板灰等 8 種主題。
*   **紙張質感**: 支援疊加經典紙紋、羊皮紙、亞麻布紋、仿舊紙、水紋紙等物理紋理底紋。

### 3. 🎙️ 高保真神經網路 TTS 朗讀
*   **Edge 官方音質**: 直連微軟 Edge 神經網路雲端 TTS，支援曉曉、雲希、雲健等數十種極具表現力的自然人聲。
*   **雙播放器緩衝機制**: 內部維護雙 `Audio` 播放物件交替預載與解碼，徹底消除句子切換間的卡頓與空白延遲。
*   **安全防背景掛起**: 針對 iOS / Android 行動端背景執行進行了專門的靜音保活與保活音訊軌道設計，支援鎖定螢幕/背景連續朗讀。
*   **智慧斷句**: 內置斷句解析器，可智慧識別小數點（如 3.14）及英文縮寫（如 Mr., J. F.），防止句子被粗暴截斷，並自動過濾正文中的角標、腳註符號。

### 4. 🤖 瀏覽器本地 AI 閱讀伴侶
*   **無需 Key 的本地 AI**: 對接 Chromium 瀏覽器內置的實驗性 **Prompt API (Gemini Nano)**，資料完全本地處理。
*   **三大 AI 能力**: 支援**一鍵劃詞釋義**、**選中段落/章節摘要**、以及**流式文字離線翻譯**。
*   **自訂 AI 與本地 LLM**: 支援接入 OpenAI、DeepSeek 等雲端大語言模型介面，以及本地部署的 Ollama、LM Studio 實例。

### 5. 📊 深度閱讀數據統計
*   **全局概覽**: 統計總閱讀時長、閱讀天數、累計閱讀書籍。
*   **單本分析**: 展示單本書的閱讀明細、日均閱讀時長。
*   **時間段分佈**: 可視化展示 24 小時閱讀時間分佈，洞察您的閱讀習慣。
*   **每日明細**: 日曆熱力圖式記錄每日閱讀時間，見證閱讀足跡。

### 6. 📁 書庫管理與備份還原
*   **分類管理**: 支援新建資料夾、重新命名，可批次移動書籍、批次刪除。
*   **全量備份**: 一鍵匯出包含**所有書籍檔案、閱讀進度、劃線、高亮、筆記以及閱讀統計**在內的加密/壓縮備份包 (`.zip`)。

## 🛠️ 架構設計

專案採用純前端驅動架構，資料統一儲存於瀏覽器本地的 **IndexedDB** 中。根據執行環境不同，設計了三種分發部署模式：

```
                               ┌────────────────────────┐
                               │    Core Application    │
                               │ (i18n, Parsers, Engine)│
                               └───────────┬────────────┘
                                           │
                   ┌───────────────────────┼───────────────────────┐
                   ▼                       ▼                       ▼
        ┌─────────────────────┐ ┌─────────────────────┐ ┌─────────────────────┐
        │   Extension Mode    │ │   Web Server Mode   │ │  Standalone Offline  │
        │ (Chrome/Edge MV3)   │ │ (Node.js + PWA App) │ │    (Single HTML)    │
        └──────────┬──────────┘ └──────────┬──────────┘ └──────────┬──────────┘
                   │                       │                       │
          declarativeNetRequest        WebSockets API         IndexedDB + base64
          動態修改請求標頭繞過         透過 node.js 服務      Data URL 繞過 Chrome
          Bing TTS 的 CORS 校驗        代理轉發 TTS 流量      file:// 安全策略限制
```

### 1. 瀏覽器擴充功能模式 (Extension Mode)
*   **實現原理**: 遵循 Chrome Extension Manifest V3 規範。
*   **核心優勢**: 能夠利用 `chrome.declarativeNetRequest` 動態修改請求標頭，將 WebSocket 連往 `speech.platform.bing.com` 的請求 Origin 強行改寫為 `chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold` (Edge 官方 TTS 擴充功能 ID)，直接獲取官方神經網路介面權限。
*   **背景通信**: `service-worker.js` 在背景攔截並代理 TTS 語音列表獲取，解決瀏覽器跨域（CORS）屏障。

### 2. 本地網頁服務模式 (Web Server Mode)
*   **實現原理**: 由 `server.js` 提供基於 Node.js 的微服務。
*   **介面代理**: 針對不支援擴充功能環境的普通瀏覽器，在服務端建立 `/api/voices` 介面和 `/api/tts` (WebSocket) 代理，將請求包裝後轉發給 Bing 伺服器，突破瀏覽器的 CORS 來源策略限制。
*   **PWA 支援**: 集成了 `sw.js` 與 `manifest.webmanifest`，開啟離線靜態資源快取，在斷網時依然可以秒級載入閱讀器主介面。

### 3. 單檔案離線模式 (Standalone Offline Mode)
*   **實現原理**: 提供一個無額外依賴的離線大 HTML 檔案 `reader_offline.html`。
*   **打包技術**: 透過建構指令碼 `scratch/compile_offline.js`，將 `JSZip` 庫、所有格式解析模組、CSS 樣式、TTS 控制指令碼及多語言 JSON 包直接內聯嵌入到 HTML 的 `<script>` 和 `<style>` 中。
*   **本地安全規避**: 在 `file://` 協定下執行時，由於 Chrome 安全機制限制，無法直接透過 `URL.createObjectURL(blob)` 連續播放音訊，會觸發 `ERR_REQUEST_RANGE_NOT_SATISFIABLE` 報錯。離線版在 TTS 引擎中自動將 Blob 轉換為 Base64 格式的 Data URL 傳入播放器，徹底解決了本地單檔案無法連續朗讀的問題。

## 🚀 使用與建構方法

### 📦 方法 A：作為瀏覽器擴充功能安裝 (推薦)
1. 下載本專案原始碼。
2. 打開 Chrome 或 Microsoft Edge 瀏覽器，進入 **「擴充功能」** 頁面 (`chrome://extensions/` 或 `edge://extensions/`)。
3. 開啟右上角的 **「開發者模式」**。
4. 點擊 **「載入未打包的擴充功能」**，選擇專案根目錄。
5. 點擊瀏覽器工具列的擴充功能圖示，即可打開全螢幕閱讀器。

### 🌐 方法 B：本地 Node.js 網頁版執行
1. 確保已安裝 Node.js 環境。
2. 在專案根目錄執行安裝依賴：
   ```bash
   npm install
   ```
3. 啟動本地開發與代理伺服器：
   ```bash
   npm start
   ```
4. 打開瀏覽器訪問：`http://localhost:3000`。

### 💾 方法 C：建構單檔案離線版/靜態部署
1. 執行打包指令碼：
   ```bash
   npm run build:offline
   ```
2. 打包完成後，會在根目錄生成 `reader_offline.html` 和 `index.html`。
3. **直接執行**: 雙擊 `reader_offline.html` 即可在本地離線使用，支援直接拖曳書籍匯入。
4. **託管部署**: 靜態檔案可以直接上傳到 Vercel、GitHub Pages、Cloudflare Pages 等平台。專案內已附帶 `vercel.json` 配置文件。

## ⚠️ 專案局限性

1.  **DRM 版權限制**: 
    無法解析和閱讀受 DRM（數位版權管理）加密保護的電子書（例如直接從 Kindle 商店下載的受保護 `.azw3`/`.mobi` 格式，或 Adobe 加密的 `.epub` ），匯入前需先使用第三方工具進行解密去保護。
2.  **本地 AI 硬體及版本門檻**:
    AI 伴侶功能完全基於 Chromium 瀏覽器的 **Gemini Nano Prompt API**。要使用該功能：
    *   瀏覽器需為 Chrome/Edge 128+ 開發者/金絲雀版本或開啟了相應實驗性 Flag 的穩定版。
    *   需在 `chrome://flags` 中開啟 `#optimization-guide-on-device-model` (設為 Enabled BypassPerfRequirement) 和 `#prompt-api-for-gemini-nano` (設为 Enabled)。
    *   裝置需有足夠的顯存/記憶體來下載和執行本地 Gemini Nano 模型（約 1.5GB ~ 3GB 模型包）。
3.  **純靜態/離線狀態下的 TTS 限制**:
    *   如果使用靜態部署（如 Vercel 靜態頁面）或直接雙擊打開 `reader_offline.html` 且**未啟動本地 proxy 代理伺服器**時，Edge TTS 需要直連微軟伺服器。若微軟對 `speech.platform.bing.com` 的 Sec-MS-GEC 計算校驗規則進行重大升級，直連 WebSocket 可能會暫時失效。
    *   在完全沒有網路連線的實體離線狀態下，雲端神經網路 TTS 將不可用，系統會自動降級並嘗試呼叫瀏覽器本地的 Web Speech API (`speechSynthesis`)，朗讀音質會大打折扣。
4.  **IndexedDB 儲存上限與資料安全**:
    *   所有書籍和進度均儲存在當前瀏覽器網域的本地資料庫中。如果用戶手動清除了瀏覽器快取、使用了「無痕/隱私模式」或者系統磁碟空間極度不足，瀏覽器可能會自動回收 IndexedDB 空間，導致書庫資料丟失。
    *   **建議**: 強烈建議定期使用書庫主頁頂部的 **「備份書庫」** 功能匯出 `.zip` 檔案到本地妥善保存。
5.  **行動端背景播放受限**:
    *   儘管 TTS 引擎實現了雙播放器無縫銜接與靜音保活，但在部分行動端系統（如 iOS Safari 或部分強力清理背景的安卓系統）上，若離開瀏覽器時間過長，系統墓碑機制仍可能強制掛起瀏覽器程序，導致 TTS 停止播放。可透過使用獨立 App 殼或保持螢幕微亮來緩解。
